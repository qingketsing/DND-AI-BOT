# Authentication Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the authentication foundation for the Go backend: `users` + `auth_sessions`, registration/login/logout/me APIs, cookie-based auth, and request authentication middleware.

**Architecture:** Use server-managed auth sessions rather than pure JWT. PostgreSQL stores durable user and auth session data, Redis caches auth session lookups, and the browser carries an opaque `HttpOnly` cookie token. Phase 1 explicitly does not yet migrate chat session ownership or frontend pages.

**Tech Stack:** Go, PostgreSQL, Redis, `bcrypt`, `net/http`, HttpOnly cookie auth

---

## Scope

This phase includes:

- `users` and `auth_sessions` persistence
- password hashing
- opaque session token generation and hashing
- `POST /auth/register`
- `POST /auth/login`
- `POST /auth/logout`
- `GET /auth/me`
- auth middleware and request context user injection

This phase does not include:

- `sessions.user_id` migration
- `GET /sessions` for authenticated users
- session ownership enforcement
- frontend integration
- onebot integration
